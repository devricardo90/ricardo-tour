# RT-113 [RT-RB-S10-03] — Structured tour content and gallery: architecture

- Date: 2026-10-16. Sprint 10 (Jira id 177). Owner decision (15/10/2026): structured data instead of free text, to serve the Sprint 11 admin. Authorization (16/10/2026): local, isolated development; mock data allowed when marked; **no migration on the hosted database, no deploy, no merge, no price change**.
- Branch: `sprint10/tours-content` (local only). Scope: the four existing tours.

## 1. Problem
Today a tour has one photo (`Trip.imageUrl`) and its duration, category, inclusions and exclusions are encoded as text inside `Trip.description` (`lib/catalog/trip-presentation.ts` parser). There is nowhere to store meeting point, start time, languages, itinerary, requirements, accessibility, weather rule or a gallery, and no way to keep PT/EN/ES versions apart (RT-111: EN/ES pages show Portuguese).

## 2. Data model (additive)
| Model | Key | Purpose |
|---|---|---|
| `TripContent` | `tripId` (1:1 with `Trip`, cascade) | Localized structured content: summary, description, durationLabel, meetingPoint, startTimeNote, languages (ISO 639-1 codes), inclusions, exclusions, requirements, accessibility, weatherPolicy; `status` (`DRAFT` / `OWNER_APPROVED`), `source` (where every fact came from; `MOCK…` for fictitious data), `approvedAt` |
| `TripItineraryStop` | `id`, unique (`tripId`, `position`) | Ordered stops: localized title/description, optional duration in minutes |
| `TripImage` | `id`, unique (`tripId`, `position`) | Ordered gallery: `src`, localized `alt`, `isCover`, `rightsStatus` (`UNVERIFIED` / `OWNER_ATTESTED` / `LICENSED`), `rightsNote` |

Localized fields are JSON objects keyed by locale (`{ "pt": …, "en": …, "es": … }`). **No price is stored here**: prices stay on `Trip.priceCents` and change only by Owner decision (RT-119 procedure). `Trip` gains only back-relations (no column).

Database rules (CHECK, in the migration): position ≥ 0; duration > 0 when present; non-blank image `src`; `status = OWNER_APPROVED` ⇔ `approvedAt` is set. Foreign keys to `Trip` with `ON DELETE CASCADE` (only the new rows of a deleted trip are removed).

## 3. Publication limits (single gate: `lib/catalog/tour-content.ts`)
- `toTourContentView(record, locale, "public")` returns content **only** when `status = OWNER_APPROVED` and the source is not `MOCK`; images are returned only with `rightsStatus` ≠ `UNVERIFIED`; no fallback to Portuguese (missing translations stay empty).
- `"preview"` audience (rebuild lab only, 404 in production) shows everything with flags (`isMock`, `missingLocale`).
- `validateTourContent()` (editorial/governance rules, used before any approval): PT, EN and ES present for every localized field; same number of list items per locale; ISO language codes; unique stop positions; at most one cover; **no price-like text**; a `MOCK` record can never be approved; approved content needs `approvedAt` and a recorded `source`.
- The existing public page is **not changed** by RT-113: no public route reads `TripContent` yet (verified 16/10). Wiring it into `/tours/[id]` is RT-114, after the Owner's visual approval.

## 4. Migration and rollback

## Complement — 17/10/2026 (Owner authorization "RT-113 complemento do modelo de dados", local only)
**Diagnosis.** Already covered by existing fields (no new column added for them): duration (`durationLabel`), meeting point, start time, languages, inclusions, exclusions, practical/physical requirements (`requirements`), accessibility, weather (`weatherPolicy`), approval (`status`/`approvedAt`, DB CHECK), group size (`Trip.maxGuests`), children (`Trip.childrenAllowed`), physical level (`Trip.physicalLevel`), media table (`TripImage`) with rights. The minimum age (18+) is stated in the localized `requirements`; a structured age field was **not** added (no consumer needs it yet; candidate for the Sprint 11 admin). Missing and now added:

| Need | Change | Why this shape |
|---|---|---|
| FAQ (question/answer PT/EN/ES, order, per tour) | new `TripFaqItem` (tripId, position, question Json, answer Json; unique tripId+position; CHECK position ≥ 0; FK cascade) | same pattern as `TripItineraryStop` (ordered child rows, admin-friendly) |
| Public operating conditions (route changes, confirmation) | `TripContent.operationalConditions Json?` | localized text like the other TripContent fields |
| Optional third-party services | `TripContent.optionalServicesNote Json?` | inclusions/exclusions already exist; the note keeps occasional activities apart from included services |
| Media credit, video, poster, mobile rendition, duration | `TripImage` + `mediaType` (IMAGE/VIDEO, default IMAGE), `posterSrc`, `mobileSrc`, `durationSeconds`, `credit Json?` | reuses the existing media table (no parallel gallery); table name kept to avoid an invasive rename |

DB rules (CHECK): a video always has a poster and an image never has one; video-only fields empty on images; a video is never the cover; duration > 0; poster/mobile src not blank. Rights stay decided by `rightsStatus` only — a credit never makes media public.

**Gate (`lib/catalog/tour-content.ts`).** Public projection stays fail-closed: content only when `OWNER_APPROVED` and non-MOCK; `gallery` returns images only; new `videos` list with the same rights filter (UNVERIFIED never public); FAQ in stored order, per locale, no Portuguese fallback publicly; `validateTourContent` mirrors the DB CHECKs (poster, cover, duration, video fields on images, duplicate media positions) and requires PT/EN/ES for the new fields; price-like text rejected. No price, cost, margin or supplier field exists in the content tables (tested in code and in the database). The lab prototype UI is unchanged; no public route reads these tables yet.

**Migration** `prisma/migrations/20261017180000_rt113_faq_conditions_media/` (+ `rollback.sql`): generated by `prisma migrate diff` from a local database holding all previous migrations, CHECKs added by hand; additive only (no DROP/UPDATE/ALTER COLUMN); the previous RT-113 migration is not modified.
